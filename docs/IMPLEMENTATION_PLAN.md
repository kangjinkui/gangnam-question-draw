# 직원정례조례 랜덤 질문 추첨 웹앱 구현 계획 — Google Sheets 버전

> **For Hermes:** 구현 시 subagent-driven-development 방식으로 작업별 구현 → 명세 적합성 검토 → 코드 품질 검토를 수행한다.

**목표:** 직원들이 모바일 웹폼으로 구청장에게 질문을 제출하고, 운영자가 승인한 질문을 직원정례조례 현장에서 주사위 또는 돌림판 연출로 중복 없이 무작위 추첨해 대형 화면에 표출한다.

**규모 전제:** 행사 1회당 질문 최대 약 500건. 이 정도 규모에서는 별도 PostgreSQL DB 없이 Google Sheets를 데이터 저장소로 사용해도 충분하다.

**아키텍처:** Google Sheet를 운영자가 직접 확인할 수 있는 DB로 사용하고, Google Apps Script가 질문 접수·관리자 검토·랜덤 추첨·현장 표출 API와 웹화면을 제공한다. 추첨 시 Apps Script `LockService`를 사용해 동시 클릭에 따른 중복 당첨을 막고, 질문 상태와 추첨 이력을 한 번에 기록한다.

**기술 스택:** Google Sheets · Google Apps Script · HTML/CSS/JavaScript · Apps Script HTML Service · clasp(선택) · Vitest 또는 순수 JS 테스트

## 1. 최종 서비스 구성

### 1.1 직원용 질문 접수 화면

- QR 또는 링크로 모바일 접속
- 질문 필수 입력
- 부서명·직급·이름은 선택 입력
- 공개 범위 선택
  - 익명
  - 부서만 공개
  - 입력정보 공개
- 완성된 예시 질문 대신 질문 소재 힌트 제공
- 개인정보·민감정보 및 특정인 비방 입력 자제 안내
- 접수 완료 시 접수번호 표시

### 1.2 운영자용 검토 화면

- Google 계정 로그인 또는 허용 계정 목록으로 접근 제한
- 질문 상태별 조회
  - 신규
  - 승인
  - 보류
  - 제외
  - 추첨 완료
- 질문 원문은 보존
- 행사 화면에 보여줄 `공개용 질문`만 별도 편집
- 승인·보류·제외 사유와 처리자 기록
- 행사 직전 추첨 대상 잠금

### 1.3 행사장용 랜덤 추첨 화면

- 16:9 대형 화면·프로젝터 대응
- 주사위 또는 돌림판 연출 선택
- `질문 뽑기` 버튼
- 승인된 미추첨 질문 중 한 건을 무작위 추첨
- 이미 추첨된 질문은 다시 나오지 않음
- 질문 공개 후 `답변 완료` 또는 `현장 보류`
- 남은 질문 수 표시
- 행사 전체 추첨 이력 저장

## 2. 권장 운영 구조

### 2.1 배포 URL

1. **직원 접수 URL**
   - QR로 배포
   - 질문 작성과 제출만 가능
   - 시트 조회·수정 불가

2. **운영자 URL**
   - 허용된 Google 계정만 접속
   - 질문 승인·보류·제외·공개문구 수정 가능
   - 추첨 대상 잠금 가능

3. **행사장 URL**
   - 프로젝터용 전체화면
   - 질문 공개에 필요한 비식별 정보만 조회
   - 추첨 실행은 운영자 인증을 거친 제어 화면에서만 가능

### 2.2 접근권한 권장안

- Google Workspace 계정으로 운영자를 식별할 수 있으면 `Session.getActiveUser().getEmail()`과 허용 이메일 목록을 사용한다.
- 직원들이 Google 계정 없이 접수해야 한다면 접수 화면은 공개하되, 관리자 기능은 별도 배포 또는 서버 측 관리자 인증으로 분리한다.
- Google Sheet 원본 공유 권한은 행사 운영자 최소 인원에게만 부여한다.
- 질문자는 Sheet에 직접 접근하지 않고 Apps Script를 통해 행 추가만 한다.

## 4. Google Sheet 설계

스프레드시트 이름 예시: `2026 직원정례조례 질문추첨`

### 4.1 `설정` 시트

| 열 | 항목 | 예시 |
|---|---|---|
| A | 행사명 | 2026년 9월 직원정례조례 |
| B | 설정값 | 값 |
| A2 | 접수상태 | OPEN / CLOSED |
| A3 | 추첨상태 | READY / LIVE / CLOSED |
| A4 | 추첨대상잠금 | TRUE / FALSE |
| A5 | 현재표출질문ID | Q-000123 |
| A6 | 현재화면상태 | IDLE / DRAWING / REVEALED |
| A7 | 보유기간종료일 | 2026-10-08 |

### 4.2 `질문` 시트

| 열 | 필드 | 설명 |
|---|---|---|
| A | 질문ID | `Q-000001` 형식의 내부 ID |
| B | 접수시각 | 서버 시각 |
| C | 질문원문 | 직원이 입력한 원문, 수정 금지 |
| D | 공개용질문 | 행사 화면에 표시할 문구 |
| E | 부서명 | 선택 입력 |
| F | 직급 | 선택 입력 |
| G | 이름 | 선택 입력 |
| H | 공개범위 | ANONYMOUS / DEPARTMENT / FULL |
| I | 상태 | SUBMITTED / APPROVED / HELD / EXCLUDED / DRAWN |
| J | 검토사유 | 보류·제외 또는 수정 사유 |
| K | 검토자 | 운영자 이메일 |
| L | 검토시각 | 승인·보류·제외 시각 |
| M | 추첨순번 | 1, 2, 3… |
| N | 추첨시각 | 실제 추첨 시각 |
| O | 답변상태 | PENDING / ANSWERED / HELD |
| P | 제출방지키 | 중복 제출 방지용 키 |

### 4.3 `추첨이력` 시트

| 열 | 필드 | 설명 |
|---|---|---|
| A | 추첨순번 | 행사 내 순번 |
| B | 추첨시각 | 서버 시각 |
| C | 질문ID | 당첨 질문 ID |
| D | 연출유형 | DICE / WHEEL |
| E | 결과상태 | REVEALED / ANSWERED / HELD |
| F | 진행자 | 실행 계정 |

### 4.4 `감사로그` 시트

| 열 | 필드 | 설명 |
|---|---|---|
| A | 기록시각 | 서버 시각 |
| B | 처리자 | 운영자 이메일 또는 SYSTEM |
| C | 행동 | SUBMIT / APPROVE / HOLD / EXCLUDE / EDIT_DISPLAY / DRAW / ANSWER |
| D | 질문ID | 관련 질문 ID |
| E | 변경전 | JSON 문자열 |
| F | 변경후 | JSON 문자열 |
| G | 사유 | 운영자 메모 |

### 4.5 `운영자` 시트

| 열 | 필드 | 설명 |
|---|---|---|
| A | 이메일 | 허용할 Google 계정 |
| B | 역할 | REVIEWER / DRAW_OPERATOR / ADMIN |
| C | 활성여부 | TRUE / FALSE |

> `운영자`, `설정`, 질문 원문의 일부 열은 보호 범위로 설정해 일반 편집자가 직접 변경하지 못하게 한다.

## 5. Google Sheets를 DB로 사용할 때의 핵심 규칙

1. 질문 500건 규모는 시트 처리에 충분하다.
2. 매 추첨마다 시트 전체를 여러 번 읽지 않고, 필요한 열을 한 번에 배열로 읽는다.
3. 행마다 API를 반복 호출하지 않고 `getValues()`·`setValues()`로 묶어서 처리한다.
4. 추첨·상태변경은 반드시 `LockService.getScriptLock()` 안에서 처리한다.
5. 질문 ID와 추첨순번은 행 번호만 믿지 않고 별도 값으로 저장한다.
6. 운영자가 시트에서 직접 행을 삭제하거나 순서를 바꾸지 않도록 보호한다.
7. 공개 화면은 이름·원문이 포함된 전체 시트를 읽지 않고, 서버가 반환한 허용 필드만 받는다.
8. Apps Script 캐시는 남은 질문 수 등 비민감 통계에만 사용하고 당첨 결과의 기준으로 사용하지 않는다.
9. 행사 전 시트 사본과 CSV를 백업한다.
10. 행사 종료 후 정해진 보유기간에 따라 이름·직급 등 개인정보 열을 삭제 또는 비식별화한다.

## 6. 랜덤 추첨 로직

### 6.1 대상 조건

다음 조건을 모두 만족하는 질문만 후보로 삼는다.

- 상태가 `APPROVED`
- 추첨순번이 비어 있음
- 추첨대상 잠금 이후 승인목록에 포함됨

### 6.2 서버 처리 순서

1. 운영자 인증 확인
2. `LockService.getScriptLock().waitLock(5000)` 획득
3. `질문` 시트의 필요한 범위를 한 번에 읽기
4. 승인·미추첨 질문의 배열 인덱스 목록 생성
5. `Math.floor(Math.random() * candidates.length)`로 한 건 선택
6. 선택 행의 상태를 `DRAWN`으로 변경
7. 추첨순번·추첨시각 기록
8. `추첨이력`과 `감사로그`에 append
9. `설정` 시트의 현재 표출 질문 ID와 화면 상태 변경
10. 공개용 질문과 허용 신원정보만 응답
11. `finally`에서 Lock 해제

### 6.3 중복 방지

- 버튼을 연속 클릭해도 첫 요청이 Lock을 잡은 동안 다음 요청은 대기한다.
- 다음 요청은 갱신된 상태를 다시 읽으므로 같은 질문을 후보에 포함하지 않는다.
- 프런트엔드에서도 추첨 중 버튼을 비활성화하지만, 최종 중복 방지는 서버가 담당한다.

### 6.4 공정성 안내

> 운영자가 사전 승인한 미추첨 질문 중에서 시스템이 무작위로 한 건을 선택하며, 이미 나온 질문은 다시 추첨되지 않습니다.

주사위나 돌림판은 분위기를 위한 화면 연출이며 실제 당첨 결과는 서버가 정한다.

## 7. 화면 설계

### 7.1 직원 접수 화면

- 모바일 우선
- 상단 설명은 짧게 유지
- 완성형 예시 질문은 사용하지 않음
- 질문 소재 키워드만 제공
- 질문 글자 수 10~500자
- 부서명·직급·이름 선택
- 공개범위 필수 선택
- 중복 제출 방지를 위해 제출 직후 버튼 비활성화
- 네트워크 오류 시 입력 내용 유지

### 7.2 운영자 검토 화면

- 상단 집계: 총계 / 신규 / 승인 / 보류 / 제외 / 추첨완료
- 상태별 필터
- 질문 원문과 공개용질문 병렬 표시
- 승인·보류·제외 버튼
- 공개용질문 수정
- 추첨대상 잠금
- CSV 백업 버튼
- 직접 시트 편집 없이 대부분의 운영이 가능하도록 구성

### 7.3 행사장 화면

- 1920×1080 기준
- 중앙에 주사위 또는 돌림판
- 질문 추첨 전에는 남은 질문 수만 표시
- 당첨 후 질문을 큰 글자로 공개
- 질문자 정보는 공개범위에 따라 표시
- 질문이 길면 자동 축소하되 최소 글자 크기 유지
- Space: 추첨
- Enter: 답변완료
- `prefers-reduced-motion` 사용 시 단순 전환

### 7.4 돌림판 표시 방식

질문 500개를 돌림판 칸에 직접 넣지 않는다.

- 돌림판에는 색상 조각 또는 익명 번호만 표시
- 애니메이션 후 질문 카드 공개
- 질문 수가 줄어도 돌림판 디자인은 동일하게 유지
- 특정 질문 위치를 미리 알 수 없게 함

## 10. 실제 시험 계획

### 자동·구조 시험

- 입력 검증 테스트 PASS
- 공개범위 계산 테스트 PASS
- 승인 질문 필터 테스트 PASS
- 랜덤 인덱스 범위 테스트 PASS
- HTML 특수문자·스크립트 입력 안전 처리

### 시트 연동 시험

가상 질문 500건을 넣고 다음을 실제 실행한다.

1. 신규 500건 저장
2. 승인 450건, 보류 30건, 제외 20건 처리
3. 승인 450건 전부 추첨
4. 중복 당첨 수 확인
5. 누락 수 확인
6. 미승인 노출 수 확인
7. 451번째 추첨의 대상 없음 처리 확인

**합격 기준:**

- 승인 질문 중복 당첨 0건
- 승인 질문 누락 0건
- 보류·제외 질문 노출 0건
- 공개범위를 벗어난 이름·부서 노출 0건
- 질문 상태와 추첨이력 불일치 0건

### 사람 검토·승인

자동시험과 별도로 담당자가 다음을 승인한다.

- 질문 승인·제외 기준
- 공개용 질문 수정 기준
- 익명·부서·전체공개 표시 방식
- 개인정보 보유기간
- 행사 화면 디자인과 글자 크기
- 현장 보류 권한자
- 주사위·돌림판 연출

## 11. 위험과 대응

| 위험 | 대응 |
|---|---|
| 운영자가 시트 행을 직접 삭제·정렬 | 시트·열 보호, 앱 화면을 통한 처리, 행사 전 사본 백업 |
| 동시 클릭으로 같은 질문 추첨 | Apps Script `LockService`와 서버 상태 재조회 |
| Apps Script 일시 지연 | 추첨 중 안내, 중복 클릭 차단, 5초 Lock 대기 후 안전한 재시도 |
| Apps Script 할당량 | 질문 500건 규모에서는 충분하나 행사 전 실제 계정으로 연속 호출 시험 |
| 익명 질문에 개인정보 포함 | 사전 안내, 운영자 승인, 원문과 공개용질문 분리 |
| 관리자 URL 유출 | Google 계정 허용목록과 서버 함수별 권한검사 |
| 질문 500개를 돌림판에 표시해 복잡해짐 | 색상·익명 번호만 연출하고 당첨 후 질문 공개 |
| 네트워크 장애 | 행사 전 승인목록 CSV와 비상용 오프라인 추첨본 준비 |
| 시트를 DB로 사용해 변경 이력 훼손 | 보호범위, 감사로그, 행사 전후 사본 보존 |

## 13. 구현 전 확인할 사항

1. 강남구 직원들이 Google 계정 로그인 없이 접수해야 하는지
2. 운영자가 사용할 수 있는 Google 계정이 있는지
3. 인터넷 공개 Apps Script 웹앱 사용이 기관 보안정책상 가능한지
4. Google Sheet 원본을 관리할 담당자와 공유 범위
5. 질문자의 부서·직급·이름을 실제 행사 화면에 공개할지
6. 접수 기간과 개인정보 보유기간
7. 주사위를 먼저 만들지, 돌림판을 먼저 만들지
8. 행사장 인터넷 장애 시 오프라인 비상화면까지 필요한지
